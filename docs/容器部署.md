# Gateway 容器部署

Gateway 是无状态数据面：代理 `/auth/*` 与 `/runtime/v1/*` 到 Identity，按 Registry 快照把业务 HTTP 转到各模块，并托管四端 Host。本仓库不拥有业务数据库，也不注册 Module Release。

## 完整环境

```powershell
pwsh -File .\deploy-local-containers.ps1
```

默认保留 MySQL 命名卷。需要空库时才加 `-Fresh`。

根脚本在 Registry 就绪、Platform 已注册且 Identity 已激活之后才启动本 Compose，避免浏览器看到半投影运行时。

## 本模块脚本

```powershell
pwsh -File .\business\backend\tools\up-local.ps1
pwsh -File .\business\backend\tools\up-local.ps1 -Fresh
pwsh -File .\business\backend\tools\down-local.ps1
```

| 脚本 | 作用 |
|---|---|
| `tools/up-local.ps1` | 校验 Registry 与 Identity 就绪，启动 Gateway 与 Admin / Merch / Shop / Live Host |
| `tools/down-local.ps1` | 停止本 Compose 项目 |

Gateway 没有 `register-local.ps1`：它只消费 Registry，不发布业务 Manifest。

## 依赖

- 外部网络 `liveshop-local`
- Registry `http://127.0.0.1:18070/readyz`（容器内 `registry:18070`）
- Identity `http://127.0.0.1:18092/readyz`（容器内 `identity:18092`）

配置文件：`business/backend/configs/gateway.compose.yaml`。CORS 只允许 Host 与各模块 artifact origin。

## 端口与服务

| 服务 | 地址 |
|---|---|
| Gateway | `http://127.0.0.1:18081` |
| Admin Host | `http://127.0.0.1:15173` |
| Merchant Host | `http://127.0.0.1:15174` |
| Shop Host | `http://127.0.0.1:15175` |
| Live Host | `http://127.0.0.1:15176` |

浏览器只打 Gateway 与 Host。模块后端 origin（如 `catalog:18090`）留在容器网络内。

## Compose 与镜像

- Compose：`business/backend/deploy/compose.local.yml`
- 后端：`business/backend/Dockerfile`
- Host 前端：`business/deploy/frontend.Dockerfile`（`npm ci` 从 npmjs 安装 `@liveshops/host-sdk@0.3.4` 与 `@liveshops/design-tokens@1.5.3`，不 COPY Platform 源码）

## 常见失败

- `/readyz` 503：Identity 投影或 Registry 快照未收敛。等 Identity 注册完成后再启动本模块。
- CORS 失败：核对 `gateway.compose.yaml` 的 `surface_origins`，容器内使用服务名而不是 `127.0.0.1` 作为模块 origin。
